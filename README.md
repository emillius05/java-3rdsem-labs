## Задание №7: Обработка строк и регулярные выражения

- **Реализована задача Варианта А (№7)**: Написан сервис `TextCleanerService`, удаляющий из текста все символы, кроме пробелов, не являющиеся буквами, с сохранением одного пробела между последовательностями подряд идущих букв[cite: 5].
- **Реализована задача Варианта C (№7)**: Написан сервис `FileMaskMatcherService`, проверяющий соответствие имени файла заданной маске, поддерживающей спецсимволы `?` (ровно один произвольный символ) и `*` (произвольное количество любых символов)[cite: 5].
- **Реализовано решение каждой задачи двумя способами**: Оба алгоритма реализованы как с использованием методов класса `String` и регулярных выражений (`replaceAll`, `matches`), так и с применением `Stream API` (`Pattern.split`, `chars()`, `Collectors.joining`)[cite: 5].
- **Обязательно применены регулярные выражения**: Для фильтрации символов, нормализации пробелов и преобразования файловой маски в регулярное выражение использованы `java.util.regex.Pattern` и регулярные выражения с поддержкой Unicode (`\p{L}`) и экранированием спецсимволов[cite: 5].

## Выполненные требования к архитектуре и коду

- **Выдержано разделение ответственности**: Чтение входных данных вынесено в класс `TextFileReader` (пакет `reader`), логика очистки текста — в `TextCleanerService`, а проверка масок имён файлов — в `FileMaskMatcherService` (пакет `service`).
- **Соблюдена строгая пакетная структура Maven-проекта**: Классы приложения распределены по пакетам `reader` и `service`, конфигурация логирования размещена в `src/main/resources`, а модульные тесты — в `src/test/java`.
- **Оформление кода приведено к Java Code Convention**: Имена классов, методов, констант, переменных и модификаторы доступа соответствуют стандартам оформления кода на Java.
- **Реализована проверка входных данных и обработка ошибок**: Предусмотрена валидация входных строк, имён файлов и масок с генерацией `IllegalArgumentException` при передаче `null` или пустых значений.
- **Интегрирована система логирования Log4j2**: Подключены библиотеки `log4j-api` и `log4j-core`, настроен цветной вывод логов уровней `DEBUG`, `INFO`, `WARN`, `ERROR` в консоль и запись в файлы с ротацией и архивацией.
- **Подготовлены модульные тесты JUnit Jupiter**: В классе `StringTasksTest` написаны тесты, проверяющие идентичность результатов обоих подходов (`String` и `Stream API`), граничные случаи и работу с входным файлом `data/input.txt`.
- **Пользовательский интерфейс не реализован**: Проверка работоспособности выполняется через запуск автоматизированных модульных тестов (`mvn clean test`).
