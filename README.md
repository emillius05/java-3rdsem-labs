## Задание №7: Европа

- **Создан класс Европа с внутренним классом TerritorialChange**: Реализована модель истории территориального деления Европы на государства[cite: 8]. Внутренний класс `TerritorialChange` содержит сведения о годе изменения, описании события, названии государства, площади в квадратных километрах и статусе[cite: 11].
- **Реализовано управление историей территориальных изменений**: Добавлены методы для добавления записей, чтения данных из внешнего файла и работы с коллекцией исторических изменений[cite: 11].
- **Организовано хранение истории изменений**: История сохраняется в структурированном виде, что позволяет проводить аналитические расчеты, такие как подсчет суммарной площади государств за конкретный год[cite: 11].
- **Реализован контроль операций и валидация данных**: Предусмотрена обработка ошибочных ситуаций и невалидных входных данных (некорректный год, отрицательная площадь, пустые названия государств), которые логируются и корректно игнорируются[cite: 6, 11].
- **Проведена сортировка истории изменений**: Реализована сортировка записей по годам с использованием интерфейса `Comparator`[cite: 6, 11].
- **Продемонстрировано использование анонимных классов**: Созданы анонимные классы для реализации интерфейсов фильтрации (`HistoryFilter`) и сравнения (`Comparator`), позволяющие фильтровать события по временным диапазонам и сортировать по площади на лету[cite: 11].

## Выполненные требования к архитектуре и коду

- **Реализовано разделение ответственности**: Класс `Europe` выступает в роли внешнего контейнера, внутренний класс `TerritorialChange` хранит сущность изменения, сервисные классы (`EuropeHistoryService`) отвечают за бизнес-логику (фильтрацию, сортировку, расчеты), а ридеры и парсеры — за чтение данных[cite: 6, 11].
- **Применён внутренний класс**: Класс `TerritorialChange` объявлен внутри класса `Europe` и используется для хранения информации об истории изменения территориального деления[cite: 11].
- **Применён анонимный класс**: Реализованы анонимные классы для гибкой фильтрации и кастомной сортировки объектов без создания дополнительных именованных классов[cite: 11].
- **Соблюдена пакетная структура Maven-проекта**: Классы приложения распределены по пакетам `entity`, `action`, `comparator`, `parser`, `reader`. Конфигурация логирования размещена в `src/main/resources`, а модульные тесты — в `src/test/java`[cite: 6, 11].
- **Обеспечена проверка корректности входных данных**: Реализована валидация числовых и строковых параметров с генерацией исключений `IllegalArgumentException` при передаче недопустимых значений[cite: 11].
- **Защита коллекций**: Метод получения истории возвращает неизменяемое представление коллекции (`Collections.unmodifiableList`), предотвращая несанкционированное изменение данных извне[cite: 11].
- **Интегрирована система логирования Log4j2**: Подключены библиотеки `log4j-api` и `log4j-core`[cite: 6, 11].
- **Настроено разноуровневое и гибкое логирование**: Задействованы логи разных уровней (`DEBUG`, `INFO`, `WARN`, `ERROR`). Вывод логов в консоль разделен по цветам в зависимости от уровня, а также параллельно дублируется в файлы с настроенной ротацией и архивацией старых логов в `.zip`[cite: 6, 11].
- **Подготовлены модульные тесты JUnit Jupiter**: Созданы тесты для проверки корректности создания внутреннего класса, работы парсера, сервисов фильтрации, сортировки и расчетов[cite: 6, 11].
- **Пользовательский интерфейс не реализован**: В соответствии с требованиями лабораторная работа проверяется посредством автоматизированных модульных тестов[cite: 6, 11].
- **Настроена автоматизация тестирования через Maven**: Для компиляции проекта и запуска тестов используется команда `mvn clean test`. В качестве средства запуска тестов настроен `maven-surefire-plugin`[cite: 6, 11].
