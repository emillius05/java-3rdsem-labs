## Задание №7: Мотоциклист

- **Определена иерархия амуниции**: Создана объектная модель, классифицирующая элементы экипировки мотоциклиста (шлем, куртка, перчатки, мотоботы, штаны) с сохранением базовых характеристик (название, вес, цена, степень защиты)[cite: 7, 8].
- **Экипирован мотоциклист**: Элементы экипировки успешно считываются из внешнего источника и формируют сбалансированный набор амуниции мотоциклиста[cite: 7, 8].
- **Произведен подсчет стоимости**: Сервисные методы безошибочно калькулируют общую суммарную стоимость всей экипировки[cite: 7, 8].
- **Проведена сортировка амуниции на основе веса**: Элементы экипировки упорядочиваются по возрастанию/убыванию их массы с помощью встроенных механизмов сортировки[cite: 7, 8].
- **Реализован поиск по диапазону параметров цены**: Написан алгоритм выборки, позволяющий находить в наборе элементы амуниции, стоимость которых строго укладывается в заданные границы от min до max[cite: 7, 8].

## Выполненные требования к архитектуре и коду

- **Реализована полноценная иерархия наследования**: Базовый абстрактный класс `Amunition` расширен производными классами с уникальными свойствами предметной области: `Helmet` (добавлено поле `hasVisor` — наличие визора), `Jacket` (добавлено поле `armorLevel` — уровень броневставок) и др[cite: 6, 7].
- **Выдержано разделение ответственности**: Классы-сущности пакета `entity` представляют собой чистые POJO-модели без методов бизнес-логики. Все функциональные действия (подсчет стоимости, сортировка, поиск по диапазону) вынесены в отдельный сервисный класс `MotorcyclistService`[cite: 6, 7].
- **Применена сортировка через интерфейс Comparator**: Сортировка набора амуниции по весу реализована с помощью стандартного интерфейса `Comparator`[cite: 6, 7].
- **Реализованы порождающие паттерны проектирования**: Создание объектов автоматизировано и централизовано внутри класса `AmunitionFactory` с использованием паттерна *Factory Method*[cite: 6, 7].
- **Соблюдена строгая пакетная структура**: Все классы приложения логически распределены по пакетам (`entity`, `factory`, `parser`, `action`, `reader`) в соответствии с общепринятыми стандартами Java[cite: 6, 7].
- **Оформление кода приведено к Java Code Convention**: Имена классов, методов, переменных, структура отступов и модификаторы доступа полностью соответствуют официальному руководству по стилю Java[cite: 6, 7].
- **Реализовано чтение данных из текстового файла с валидацией**: Параметры инициализации объектов считываются парсером из файла `ammunition.txt`[cite: 6, 7]. Среди входных строк присутствуют как корректная информация, так и заведомо поврежденные данные (отрицательные цены/вес, текстовый мусор). Реализована отказоустойчивая обработка — поврежденные строки логируются и игнорируются, не прерывая выполнение программы[cite: 6, 7].
- **Интегрирована современная система логирования**: Подключена библиотека Log4j2[cite: 6, 7].
- **Настроено разноуровневое и гибкое логирование**: Задействованы логи разных уровней (`DEBUG`, `INFO`, `WARN`, `ERROR`). Вывод логов в консоль разделен по цветам в зависимости от уровня, а также параллельно дублируется в файлы. Настроена ротация: текущие логи распределяются по файлам, а устаревшие архивируются в `.zip`[cite: 6, 7].
- **Обеспечено полное покрытие юнит-тестами**: Весь написанный код полностью покрыт тестами с помощью фреймворка JUnit 5[cite: 6, 7].
- **Пользовательское меню для приложения не реализовано**: В соответствии с требованиями задание демонстрирует свою работоспособность исключительно через запуск автоматизированных тестов[cite: 6, 7].
